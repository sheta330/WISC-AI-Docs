Core Principle: Additive Architecture

Every new feature = New layer from outside | Core Logic = Protected & Frozen

🏗️ The Architecture Stack (4 Layers)

Hover over any component to see detailed explanation

Layer 4: Presentation (API Controllers)

User entry point - HTTP/API Layer

UnifiedSmartQueryController
🎯 Main API Entry Point

Primary controller for AI-powered natural language queries. Handles JWT authentication, request validation, session management, and delegates to service layer.

Route: POST /api/v2/UnifiedSmartQuery/query
AiChatController
💬 Legacy Chat Endpoint

Original chat controller maintained for backward compatibility. Handles conversational AI interactions with context memory.

Legacy: Maintained for existing clients
HealthController
🏥 System Health Monitor

Provides health check endpoints for monitoring system status, database connectivity, and AI service availability.

Routes: /health, /health/ai

Layer 3: Service Decorators (Additions)

New features (Additive-Only) - Decorator Pattern Stack

Feature Decorators (New)
🆕 Your New Decorators Here

Extension point for new features. Create decorators that wrap existing services to add behavior without modifying core logic.

Pattern: Decorator → wraps inner service
PersonaEnhancedQueryService
🎭 Arabic Persona Formatter

Adds Egyptian Arabic persona to responses. Transforms technical outputs into friendly, culturally-appropriate messages.

Sprint B: Response formatting layer
SecureSmartQueryService
🔒 Security Validator

Validates tenant isolation and cross-tenant safety. Ensures queries only access authorized tenant data.

GAP-2: Cross-tenant validation
SmartQueryServiceV2 (Core 🔒)
⚙️ Core Service (FROZEN)

The immutable core containing SQL generation logic. NEVER MODIFY. All extensions must use Decorator pattern.

🔒 Frozen - Use Decorators to extend

Layer 2: Orchestration (The Brain)

AI coordination layer - Core Intelligence

RagOrchestrator
🎯 Main AI Coordinator

Central orchestrator that coordinates all AI components. Manages query flow from intent classification to SQL execution.

Core: RAG (Retrieval Augmented Generation)
StrictProductionOrchestrator
🛡️ Production-Grade Orchestrator

3-Level Protocol: Tool → Semantic SQL → Metadata Fallback. Strict validation for production environments.

Protocol: Tool-First with SQL Fallback
CommandGenerator
🧠 SQL Generator

Generates SQL queries from natural language using LLM. Builds prompts with metadata context and smart tags.

Uses: OllamaProvider + Metadata
IntentClassifier
🔍 Intent Detector

Classifies user intent from Egyptian Arabic or English queries. Determines query type: Balance, Transaction, Invoice, etc.

Languages: Egyptian Arabic (Ammiya) + English
QueryDecomposer
📊 Query Breakdown

Breaks complex multi-part queries into simpler sub-queries for sequential processing.

Example: "Show sales AND top customers" → 2 queries

Layer 1: Infrastructure (The Engine)

Engine & storage - External Services

OllamaProvider
🤖 Local LLM Provider

Connects to local Ollama instance (http://localhost:11434). Strictly offline - no cloud APIs for security.

Model: llama3.2 (configurable)
SqliteVectorStore
💾 Vector Database

SQLite-based vector store for semantic search and RAG. Stores embeddings for offline similarity search.

File: wisc_vectors.db
TokenLimiter
📏 Context Compressor

4-Layer Constructive Compression: Schema → Samples → Knowledge → SmartTags. Optimizes LLM context window.

Budget: Configurable token limit
EmbeddingProvider
🔢 Vector Embedder

Generates vector embeddings for semantic search. Uses Ollama embeddings for similarity matching.

Purpose: RAG semantic retrieval

🔄 Data Flow

1

UnifiedSmartQueryController

Extract Tenant/User from JWT → Validate ModelState → Resolve Session

2

ISmartQueryServiceV2 (Decorator Stack)

SecureSmartQueryService (checks tenant) → PersonaEnhancedQueryService (Arabic formatting)

3

SmartQueryServiceV2 (Core - Frozen)

Build context (metadata + smart tags) → Call RagOrchestrator

4

RagOrchestrator (The Brain)

Intent Classification (Egyptian/English) → Command Generation (SQL from LLM) → Secure Execution

5

Response

Data (JSON) + Generated SQL (transparency) + Metadata (tokens, steps, intent)

📝 Integrative Development Pattern (Step-by-Step)

1. Feature Flag

appsettings.json → "FeatureFlags:EnableX": false

2. Interface (Contract)

public interface IXService { }

3. Implementation

public class XService : IXService { }

4. Decorator

Wrap ISmartQueryServiceV2 if needed

5. Registration

Program.cs → Add to decorator stack

6. Toggle

Set flag → true (when ready)
