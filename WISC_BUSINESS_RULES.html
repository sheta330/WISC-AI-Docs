🛡️ Trust Layer Architecture

The Trust Layer validates all operations against business rules BEFORE database execution. Violations are rejected at the SecureSmartQueryService decorator level.

1

SQL Generation

CommandGenerator produces SQL from natural language

2

Trust Layer Validation

SecureSmartQueryService validates against Business Rules Registry

3

Decision

✓ ALLOW → Execute SQL | ✗ DENY → Return SecurityError

💰 Financial Integrity Rules

💵
Balance Constraints
HIGH SEVERITY
  • NO_OVERDRAFT: Cannot withdraw/transfer amount greater than available balance
  • POSITIVE_AMOUNT: All transaction amounts must be positive numbers (sign determined by transaction type)
  • CURRENCY_MATCH: Multi-currency operations must specify exchange rate
  • PRECISION_LIMIT: Decimal precision limited to 2 places for display, 6 for exchange rates
🚫 Violation Example

User Query: "Withdraw 20,000 from Ahmed" (Balance: 15,000)

// Trust Layer blocks this query { "errorCode": "InsufficientBalance", "errorMessage": "Withdrawal amount exceeds available balance. Max allowed: 15,000 EGP", "errorType": "BusinessRuleViolation" }
📊
Double-Entry Accounting
HIGH SEVERITY
  • DEBIT_EQUALS_CREDIT: Total debits must equal total credits in every transaction
  • CHART_OF_ACCOUNTS: All entries must reference valid Chart of Accounts codes
  • NO_ORPHAN_ENTRIES: Every transaction detail must belong to a parent transaction
  • PERIOD_VALIDITY: Cannot post to closed accounting periods

🔧 Implementation Note

Enforced via database trigger OR application validation in SecureSmartQueryService. Recommendation: Database-level constraint for absolute integrity.

🗄️ Data Integrity Rules

🏢
Tenant Isolation
CRITICAL SECURITY
  • TENANT_BOUNDARY: Every query MUST include TenantId filter
  • NO_CROSS_TENANT: Cannot JOIN tables across different tenants
  • TENANT_SUBQUERY: Subqueries must maintain tenant scope
  • SESSION_VALIDATION: Session must belong to authenticated tenant
// SQL Injection Check Example // Query MUST have: WHERE TenantId = @tenantId if (!sql.Contains("TenantId")) { throw new SecurityException("CrossTenantViolation: Missing tenant filter"); } // Parameterized tenant injection cmd.Parameters.AddWithValue("@tenantId", currentUser.TenantId);
📝
Immutable Records
MEDIUM SEVERITY
  • NO_HARD_DELETE: Financial records cannot be deleted (soft delete only)
  • REVERSE_TRANSACTION: Corrections must use reversing entries
  • AUDIT_TRAIL: All changes require user attribution and timestamp
  • ARCHIVE_BEFORE_DELETE: Records must be archived before soft delete
🚫 Blocked Operations
  • DELETE FROM Transactions (❌ BLOCKED)
  • UPDATE TransactionDate to past date (❌ BLOCKED if period closed)
  • Direct balance modification (❌ MUST use transactions)

⚙️ Operational Rules

📅
Date & Period Rules
MEDIUM SEVERITY
  • FUTURE_DATE_LIMIT: Cannot post transactions more than 30 days in future
  • CLOSED_PERIOD: Cannot modify transactions in closed accounting periods
  • DATE_SEQUENCE: Transaction date cannot be before customer creation date
  • YEAR_BOUNDARY: Cross-year adjustments require special authorization
📦
Inventory & Stock
LOW SEVERITY
  • NEGATIVE_STOCK: Can allow negative stock for backorders (configurable)
  • STOCK_RESERVATION: Reserved stock cannot exceed available quantity
  • COST_VALIDATION: Unit price cannot be below cost price (configurable)

🤖 AI Security Rules

🤖
SQL Generation Guards
CRITICAL SECURITY
  • NO_DROP_TABLE: AI cannot generate DROP, TRUNCATE, or ALTER statements
  • NO_GRANT: AI cannot generate GRANT, REVOKE permission statements
  • READ_ONLY_COLUMNS: AI cannot UPDATE computed columns (Balance, etc.)
  • PARAMETERIZED_ONLY: All user input must be SQL parameterized
  • TIMEOUT_LIMIT: AI queries limited to 30 seconds execution
// SQL Validation in SecureSmartQueryService private readonly string[] _forbiddenKeywords = new[] { "DROP", "TRUNCATE", "ALTER", "GRANT", "REVOKE", "CREATE", "DELETE" // DELETE requires soft-delete logic }; public void ValidateSql(string sql) { var upperSql = sql.ToUpperInvariant(); foreach (var keyword in _forbiddenKeywords) { if (upperSql.Contains(keyword)) throw new SecurityException($"Forbidden SQL keyword detected: {keyword}"); } }
🔍
Smart Tag Validation
HIGH SEVERITY
  • ROLE_VIEW_ONLY: Columns with [Role:View] cannot be in UPDATE statements
  • TABLE_WHITELIST: AI can only query whitelisted tables
  • COLUMN_WHITELIST: Sensitive columns (PasswordHash, etc.) are blacklisted

🔧 Smart Tag Security Example

// Balance column has [Role:View] tag // This UPDATE would be rejected: // UPDATE Customers SET Balance = 10000 WHERE... if (sql.Contains("UPDATE") && sql.Contains("Balance")) { var columnRole = GetColumnRole("Customers", "Balance"); // Returns: View if (columnRole == ColumnRole.View) throw new SecurityException("Cannot UPDATE computed column: Balance"); }

🔧 Implementation Guide

💻
SecureSmartQueryService Integration
// WISC.AI.Mind/Services/SecureSmartQueryService.cs public class SecureSmartQueryService : ISmartQueryServiceV2 { private readonly ISmartQueryServiceV2 _inner; private readonly IBusinessRuleValidator _ruleValidator; public async Task<SmartQueryResponseV2> ExecuteAsync( SmartQueryRequestV2 request, CancellationToken ct) { // 1. Get generated SQL from inner service (preview mode) var preview = await _inner.PreviewAsync(request, ct); var sql = preview.GeneratedSql; // 2. TRUST LAYER: Validate against Business Rules var validation = await _ruleValidator.ValidateAsync(sql, request.TenantId); if (!validation.IsValid) { return new SmartQueryResponseV2 { Success = false, ErrorCode = validation.ViolatedRule, ErrorMessage = validation.ErrorMessage, ErrorType = "BusinessRuleViolation" }; } // 3. All rules passed - execute actual query return await _inner.ExecuteAsync(request, ct); } }
