🎯 What is the Decorator Pattern?

Simple Definition

Decorator Pattern = You wrap an object inside another object, and the outer adds new behavior without modifying the inner.

Practical Example: Onion Layers 🧅

🎭 Layer 3: PersonaEnhancedQueryService

Adds Arabic formatting to the response

↓ wrap

🔒 Layer 2: SecureSmartQueryService

Adds Security validation (cross-tenant)

↓ wrap

⚙️ Layer 1: SmartQueryServiceV2 (Core)

Core logic - Frozen and untouched 🔒

📐 Structure in Code

Step 1: Interface (Contract)

// The contract all Decorators must implement public interface ISmartQueryServiceV2 { Task<SmartQueryResponseV2> ExecuteAsync( SmartQueryRequestV2 request, CancellationToken ct); }

Step 2: Core Implementation (Frozen)

// This is the Core - DO NOT TOUCH! 🔒 public class SmartQueryServiceV2 : ISmartQueryServiceV2 { public async Task<SmartQueryResponseV2> ExecuteAsync(...) { // Core logic for SQL generation // Validated and tested - DO NOT MODIFY! var result = await _ragOrchestrator.ProcessQuery(...); return result; } }

Step 3: Decorator Implementation

// Decorator wraps Core and adds Security public class SecureSmartQueryService : ISmartQueryServiceV2 { private readonly ISmartQueryServiceV2 _inner; private readonly TenantScopedValidator _validator; public SecureSmartQueryService( ISmartQueryServiceV2 inner, TenantScopedValidator validator) { _inner = inner; _validator = validator; } public async Task<SmartQueryResponseV2> ExecuteAsync(...) { // === NEW BEHAVIOR: Security Check === var validation = await _validator.ValidateAsync(request); if (!validation.IsValid) throw new SecurityException("Cross-tenant violation detected"); // === DELEGATE TO INNER === return await _inner.ExecuteAsync(request, ct); } }

Step 4: Another Decorator (Persona)

// Another decorator wraps Secure and adds Arabic formatting public class PersonaEnhancedQueryService : ISmartQueryServiceV2 { private readonly ISmartQueryServiceV2 _inner; private readonly IConfiguration _config; public async Task<SmartQueryResponseV2> ExecuteAsync(...) { // === DELEGATE TO INNER FIRST === var result = await _inner.ExecuteAsync(request, ct); // === NEW BEHAVIOR: Format Response === if (_config["Features:PersonaResponses"] == "true") { result.Message = FormatInArabicPersona(result.Message); } return result; } private string FormatInArabicPersona(string message) { return $"Hello! 👋\n{message}\nIf you need anything else, I'm at your service! 😉"; } }

🔗 Registration in Program.cs

// ============================================= // Decorator Stack Registration // ============================================= // 1. Register Core (Concrete) builder.Services.AddScoped<SmartQueryServiceV2>(); // 2. Register Decorator Stack as Interface builder.Services.AddScoped<ISmartQueryServiceV2>(sp => { // Get dependencies var innerService = sp.GetRequiredService<SmartQueryServiceV2>(); var tenantValidator = sp.GetRequiredService<TenantScopedValidator>(); var securityLogger = sp.GetService<ILogger<SecureSmartQueryService>>(); var personaLogger = sp.GetRequiredService<ILogger<PersonaEnhancedQueryService>>(); var config = sp.GetRequiredService<IConfiguration>(); // Layer 1: Core service // Layer 2: Security decorator (GAP-2) var securityWrapped = new SecureSmartQueryService( innerService, // ← wrap this tenantValidator, securityLogger, config); // Layer 3: Persona decorator (Sprint B) - Outermost return new PersonaEnhancedQueryService( securityWrapped, // ← wrap security personaLogger, config); });

Caller sees: ISmartQueryServiceV2

→ PersonaEnhancedQueryService

↓ calls _inner

→ SecureSmartQueryService

Security validation + tenant checks

↓ calls _inner

→ SmartQueryServiceV2 (Core)

Actual SQL generation logic

⚖️ Decorator vs Inheritance

Aspect Inheritance Decorator Pattern ✅
Core Modification Must inherit and modify Wrap from outside - Core untouched
Adding Features New class for every combination New Decorator = New feature
Runtime Behavior Fixed compile-time Flexible - Decorators chained
Testability Hard to test in isolation Mock inner service easily
Feature Flags Complex Decorator on/off via config

📝 Step-by-Step: Creating a New Decorator

1Feature Flag

Add flag in appsettings.json to enable/disable the feature

"FeatureFlags:EnableCachingDecorator": true

2Class Implementation

public class CachingQueryService : ISmartQueryServiceV2 { private readonly ISmartQueryServiceV2 _inner; private readonly IMemoryCache _cache; public CachingQueryService(ISmartQueryServiceV2 inner, ...) { _inner = inner; // ← wrap _cache = cache; } public async Task<SmartQueryResponseV2> ExecuteAsync(...) { // Check cache first var cacheKey = GenerateCacheKey(request); if (_cache.TryGetValue(cacheKey, out var cached)) return cached; // Delegate to inner var result = await _inner.ExecuteAsync(request, ct); // Cache result _cache.Set(cacheKey, result, TimeSpan.FromMinutes(5)); return result; } }

3Registration

Add Decorator to the stack in Program.cs

// Layer 4: Caching (newest) // Layer 3: Persona // Layer 2: Security // Layer 1: Core var personaWrapped = new PersonaEnhancedQueryService(securityWrapped, ...); return new CachingQueryService(personaWrapped, cache, config);

4Test

Test the Decorator isolated with Mock for inner service

[Fact] public async Task CachingDecorator_ReturnsCachedResult() { // Arrange var mockInner = new Mock<ISmartQueryServiceV2>(); var decorator = new CachingQueryService(mockInner.Object, cache); // Act var result = await decorator.ExecuteAsync(request); // Assert mockInner.Verify(x => x.ExecuteAsync(...), Times.Once); }

⚠️ Common Pitfalls

❌ Mistake 1: Modifying Core

If you want to add a feature, don't modify SmartQueryServiceV2 - create a new Decorator!

⚠️ Mistake 2: Forgetting to Register

The Decorator won't execute by itself - you must register it in Program.cs and add to the stack

💡 Tip: Order matters!

Decorator order is important - Security should be close to Core, Persona outside
